# 퀘스트 C-2: 에이전트 코드리뷰 (에이전트 버전, 코드 페어리뷰)

출처: 사용자가 보여 준 LMS 퀘스트 안내와 Review.md 템플릿 화면(2026-10-30).
표시: **(안내)** = 퀘스트 안내에 적힌 내용, **(사용자 확인)** = 사용자가 직접 알려 준 완화 조건, **(보충)** = 제 정리.
이 퀘스트의 날짜·페어·팀은 아직 모른다.

## 1. 요약 (안내)
- **개발자(Developer)** 가 에이전트로 개발한 결과물을 **리뷰어(Reviewer)** 가 검토한다. 리뷰하는 **과정 전체를 화면공유**로 보여 준다.
- 목표는 **상호보완적 학습**으로 에이전트 활용 노하우(**프롬프트·검증·보안**)를 교환하는 것.
- 개발자: 내가 쓴 코드의 의도와 내용을 상대가 **이해하기 쉽게 설명**한다.
- 리뷰어: 상대 코드를 이해하고 **장점은 배우고, 개선점·제안은 나눈다.** 템플릿 기준으로 리뷰하고 기록한다.
- (안내에 템플릿 이름이 PRT(Peer Review Template)와 ART(Agent Review Template) 두 가지로 적혀 있다. 실제 파일은 **ART**다.)

## 2. 점수 (안내)
- 리뷰어가 쓴 **Review.md의 ART**를 근거로 퍼실이 평가한다. **기능 동작 여부, 프롬프트 품질, 보안 검토** 중심.
- 리뷰가 잘 쓰인 경우: **코더가 Pass(+1)** 를 얻는다.
- 리뷰가 **불성실**하다고 판단되면: **리뷰어에게 Penalty(-1점).**
- 불성실한 리뷰로 제대로 리뷰되지 않은 코드는 **퍼실이 코더의 코드를 직접 확인**해 Pass 여부를 정한다.

## 3. 진행 방법 (안내): 팀별 온라인 공간, 마이크·화면 공유 가능
| 순서 | 개발자 | 리뷰어 |
|---|---|---|
| 1 | 팀별로 마이크/화면 공유가 가능한 온라인 공간에 모이기 | (같음) |
| 2 | **30분 동안** 서로 결과물에 대한 피드백을 나눈다. **과정 전체 화면 공유!**<br>① 리뷰어에게 **레포지토리 주소 공유**<br>② 화면공유로 에이전트에게 **요청한 내용과 결과물**을 이해하기 쉽게 설명 | ① 개발자의 레포지토리를 **fork 후 clone**<br>② 개발자의 설명을 들으며 **ART 리뷰 작성**: 항목 앞 `[ ]`에 해당하면 **O**, 아니면 **X**<br>③ **각 항목마다 근거 첨부** (실행 화면·코드·이미지) |
| 3 | 요청 온 **Pull Request 확인 후 내 레포지토리에 Merge** | 수정한 **Review.md를 Commit & Push**하고 **Pull Request** 보내기 |
| 4 | **역할을 바꿔** 같은 과정을 진행 | (같음) |

## 4. 유의사항 (안내)
- **Peer Review는 동료를 상처 입히는 것이 아니다.** 가장 크고 명확한 규칙.
- **맞다, 틀리다를 평가하지 않는다.** 의견을 나누는 자리이므로 **코더가 꼭 본인 코드를 수정할 필요는 없다.**
- 다른 관점에서 생각하는 법, 미처 생각하지 못한 부분을 발견하는 것이 성장에 큰 도움이 된다.

## 5. ART 항목과 이번 적용 범위
| 번호 | 항목 | 필수 여부 |
|---|---|---|
| 1 | 원하는 기능이 의도한 대로 동작하나요? (요청한 기능이 구현됐는지, **실행 화면·결과물 캡처를 근거로**) | **필수** |
| 2 | 에이전트에게 준 요청(프롬프트)이 적절했나요? | **없어도 됨** (사용자 확인) |
| 3 | 보안 검토를 수행했나요? (키·비밀번호 하드코딩 여부, 입력값 검증, 외부 데이터·의존성 출처와 위험) | **필수** |
| 4 | 에러가 난 부분을 디버깅하여 **문제를 해결한 기록**을 남겼나요? (오류를 어떻게 발견·수정했는지, 새 시도·실험) | **필수** |
| 5 | 회고를 잘 작성했나요? | **없어도 됨** (사용자 확인) |

**(사용자 확인)** 템플릿을 **완전히 따라 쓰지 않아도 된다.** 2번·5번이 없어도 된다.

Review.md의 나머지 구성: **참고 링크, 개선 제안, 총평** (그리고 맨 위의 개발자·리뷰어 이름 칸).

## 6. 이 퀘스트에서 쓰는 앱
이 퀘스트는 **Todo 앱**을 대상으로 한다. 리뷰어가 저장소를 fork·clone해서 실행해 보므로 **로컬 모드로 실행이 되어야** 한다.
- **리뷰어에게 줄 폴더(로컬 전용): [`Todo-로컬버전/`](Todo-로컬버전/)** : SQLite로 실행되는 파일만 모은 것이다. `npm install` → `npm start`, 계정·키·`.env`가 필요 없다. 실행 방법·확인할 기능·보안 확인 포인트는 그 폴더의 README에 있다. (2026-10-30 새 설치와 API 테스트로 확인함)
- 전체 앱(클라우드 포함) 저장소: [`Gkerala/todo-app`](https://github.com/Gkerala/todo-app)
- `Todo-로컬버전`의 코드는 전체 앱에서 **그대로 복사한 스냅샷**이다. 전체 앱 코드를 고치면 이쪽도 같이 갱신해야 어긋나지 않는다.
- ART 항목 대응: **1번**(기능·실행 화면)은 폴더 README의 "확인해 볼 기능", **3번**(보안)은 "보안 확인 포인트" 표, **4번**(문제 해결 기록)은 "문제 해결 기록" 표에 있다. 2번·5번은 선택이라 따로 쓰지 않았다.
